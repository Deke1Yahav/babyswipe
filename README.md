# בייביסוויפ

אפליקציה לאיתור בייביסיטר זמינים במהירות, בסגנון טינדר: הורים מחליקים על בייביסיטרים קרובים, מסננים לפי מרחק ומחיר, מחפשים על מפה, ומתכתבים בתוך האפליקציה.

## מה יש באפליקציה

**להורים**
- הרשמה והתחברות עם אימייל וסיסמה, כולל איפוס סיסמה.
- מיקום מה-GPS של הטלפון, או בחירה ידנית על המפה.
- החלקה: ימינה לשמירה, שמאלה לדילוג, עם ביטול הפעולה האחרונה.
- סינון לפי מרחק, מחיר לשעה ו"פנויים עכשיו", ומיון לפי קרבה או מחיר.
- מפה אמיתית (OpenStreetMap) עם מסמנים של שם ומחיר ועיגול של טווח החיפוש.
- שיחות בזמן אמת עם הבייביסיטרים, עם מונה הודעות שלא נקראו.

**לבייביסיטרים**
- פרופיל עם גיל, מחיר, ניסיון, תגיות, תיאור ואזור.
- כפתור "פנוי/ה ל-3 שעות" או ל-8 שעות, כדי להופיע ראשונים להורים שמחפשים עכשיו.
- אפשרות להסתיר את הפרופיל מהחיפוש.
- מענה להודעות מהורים.

**בטיחות ופרטיות**
- המיקום של בייביסיטר נשמר רק בדיוק של כחצי קילומטר, כך שהכתובת לא נחשפת.
- מספרי טלפון ואימיילים לא מוצגים. כל ההתכתבות בתוך האפליקציה.
- חסימה ודיווח מתוך כל שיחה.
- מחיקת חשבון מלאה, כולל הפרופיל וכל ההודעות.
- כל ההרשאות נאכפות במסד הנתונים (Row Level Security), ויש להן בדיקות אוטומטיות.

## איך זה בנוי

- **צד לקוח:** React + TypeScript + Vite. אתר שעובד בטלפון ובמחשב, ומתפרסם ב-GitHub Pages.
- **שרת:** [Supabase](https://supabase.com): התחברות, מסד נתונים Postgres וצ'אט בזמן אמת. התוכנית החינמית מספיקה להתחלה.
- **מפה:** Leaflet עם אריחי OpenStreetMap, בלי צורך במפתח API.

```
src/                     קוד האפליקציה
supabase/migrations/     מבנה מסד הנתונים וההרשאות
supabase/tests/          בדיקות הרשאות למסד הנתונים
public/demo.html         גרסת הדוגמה הישנה (בלי שרת)
.github/workflows/       בדיקות ופרסום אוטומטי
```

## הפעלה: צעד אחר צעד

### 1. יצירת שרת ב-Supabase
1. נרשמים ב-https://supabase.com ויוצרים פרויקט חדש (New project). מומלץ לבחור אזור קרוב, למשל Frankfurt.
2. בתפריט הצד: **SQL Editor** ← **New query**. מדביקים את כל התוכן של `supabase/migrations/0001_init.sql` ולוחצים **Run**.
3. **Authentication** ← **URL Configuration**:
   - **Site URL:** `https://deke1yahav.github.io/babyswipe/`
   - תחת **Redirect URLs** מוסיפים את אותה כתובת, וגם `http://localhost:5173/` לפיתוח מקומי.
4. **Project Settings** ← **API**: מעתיקים את **Project URL** ואת המפתח **anon public**.

### 2. חיבור GitHub
1. בריפו ב-GitHub: **Settings** ← **Secrets and variables** ← **Actions** ← **New repository secret**. יוצרים שני סודות:
   - `VITE_SUPABASE_URL`: ה-Project URL
   - `VITE_SUPABASE_ANON_KEY`: המפתח anon public
2. **Settings** ← **Pages** ← תחת **Source** בוחרים **GitHub Actions**.
3. **Actions** ← **Deploy to GitHub Pages** ← **Run workflow**.

אחרי דקה-שתיים האפליקציה זמינה בכתובת https://deke1yahav.github.io/babyswipe/

המפתח anon public מיועד מראש להיות חלק מהאתר. ההגנה על המידע מגיעה מההרשאות במסד הנתונים, לא מהסתרת המפתח. לעולם לא מכניסים לאפליקציה את המפתח service_role.

### 3. לפני שמכניסים משתמשים אמיתיים
- **שליחת אימיילים:** שרת האימייל המובנה של Supabase מוגבל לכמה הודעות בשעה ומיועד לבדיקות בלבד. לפני השקה מחברים ספק אימייל (למשל Resend או SendGrid) ב-**Authentication** ← **Emails** ← **SMTP Settings**.
- **תנאי שימוש ומדיניות פרטיות:** צריך לכתוב ולפרסם אותם, כי ההרשמה מבקשת לאשר אותם. כדאי להתייעץ עם עורך דין, במיוחד כשמדובר בטיפול בילדים ובבייביסיטרים בני 16–17.
- **טיפול בדיווחים:** דיווחים נשמרים בטבלה `reports`, וצופים בהם ב-**Table Editor** בלוח הבקרה של Supabase.
- **מפה:** אריחי OpenStreetMap חינמיים לשימוש מתון. עם הרבה משתמשים עוברים לספק אריחים (למשל MapTiler), וזה שינוי של שורה אחת ב-`src/components/MapView.tsx`.

## פיתוח מקומי

```bash
cp .env.example .env.local   # ממלאים את שני הערכים מ-Supabase
npm install
npm run dev                  # http://localhost:5173
```

- `npm run build`: בדיקת טיפוסים ובנייה.
- `npm run test:db`: הרצת בדיקות ההרשאות על Postgres מקומי (צריך Postgres מותקן, ולא להריץ כ-root).

בכל push ו-pull request, GitHub Actions מריץ את הבנייה ואת בדיקות ההרשאות.

## השלבים הבאים

- תמונות פרופיל (Supabase Storage).
- ביקורות ודירוג אחרי עבודה.
- אימות זהות לבייביסיטרים.
- התראות push על הודעות חדשות.
- אפליקציה בחנויות (עטיפה עם Capacitor, או גרסה ב-React Native).
